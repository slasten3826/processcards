# Win Module Law

```text

давление: ../chaos/WIN_MODULE_ANSWERS_2026-07-29.md
кристалл: ../crystall/WIN_MODULE_SLICE_2026-07-29.md
```

Первая редакция давления — `WHY_WIN_CHECK_IS_SEPARATE_2026-07-29.md` — помечена legacy. Её формулировка «модуль не имеет права менять состояние» уточнена здесь, §3.

Этот документ называет **модуль победы**. Условие победы описывает `WIN_CHECK_LAW`; здесь названо то, что его исполняет.

## 1. Что это

```text
модуль ЯДРА
```

Он не знает ни об одном инструменте, рендерере или интерфейсе. CLI, клиент и любые внешние поверхности учатся работать с ним снаружи и никак в него не входят.

```text
это судья, а не машина
```

Машина действует. Этот модуль **выносит вердикт**.

## 2. Как к нему обращаются

```text
шаг 9 CHECK — это ВОПРОС хода, а не место модуля
```

Ход спрашивает, есть ли победа. События шага принадлежат ходу; модуль не знает, что шаги существуют.

```text
у модуля один вход
обращаются двое: ход (вопрос) и козырь (заявка)
```

Из единственности входа следует, что проверка «исход уже записан» стоит в одном месте, и переписать записанный исход нечем.

## 3. Права

```text
доска    только чтение. Ни одной карты не двигает
исход    его собственное поле, писать в него может только он
```

Модуль **завершает партию**. Это не ход: завершение не двигает карту, оно отвечает на доску.

Из исключительности права следует главное:

```text
в игре ровно одно место, где партия может кончиться
```

Если бы модуль лишь возвращал вердикт, вызывающий мог бы его не заметить.

## 4. Способы победы

Список перечислим и **открыт**.

```text
1. скомпилированный шаблон   §5, без заявителя
2. ENOUGH                    §6, по заявке. Первый из альтернативных,
                             и скорее всего не последний
```

Способы делятся по тому, кто их поднимает:

```text
без заявителя   проверяются на КАЖДОМ вопросе хода. Их может быть
                больше одного, и все они прогоняются
по заявке       проверяются, когда заявитель обратился
```

Новый способ добавляется в этот список, а не в обход него.

## 5. Грамматика компиляции

```text
трио козырей в целевых слотах 1, 2, 3
разворачивается в шесть глифов по порядку:

    слот1.верх, слот1.низ, слот2.верх, слот2.низ, слот3.верх, слот3.низ
```

Манифестная цепь сверяется с этой последовательностью **позиция в позицию**:

```text
верхнее чтение   верхний глиф каждой карты манифеста
нижнее чтение    нижний глиф каждой карты манифеста
```

Ряд выбирается один на все шесть. Смешивать нельзя.

Второй глиф карты при верхнем чтении свободен, первый при нижнем — свободен.

```text
скрытая карта в целевом слоте не компилирует
```

Козырь участвует, только если он `known` или `revealed`. Пока он скрыт, неизвестно, что он козырь, и шаблона нет.

Отсюда момент победы: шаблон в манифесте может быть собран раньше, чем компилятор достроен. Побеждает **не последний ход, а последнее раскрытие**.

Грантовые слоты порядка не сохраняют: `GRANT §6`, `§7`.

Этот раздел закрывает первый открытый пункт `WIN_CHECK_LAW §12`.

## 6. Протокол заявки

Козырь может **заявить** победу. Заявка не является победой.

```text
форма заявки принадлежит МОДУЛЮ
основание заявки принадлежит КОЗЫРЮ
```

Заявка несёт:

```text
подпись     кто заявляет
основание   почему заявитель так считает
```

Модуль **пересчитывает основание сам** по состоянию доски.

```text
сошлось      победа, с подписью заявителя
не сошлось   дефект. Заявка отвергается громко, а не молча
```

Заявка **повторяема**. Один и тот же заявитель может обращаться каждый ход, и отказ на одном ходу не запрещает заявку на следующем.

Причина, по которой повторяемость обязательна: `REQUIEM` умеет установить козырь в `runtime`, и установленный так `ENOUGH` обращается к модулю в конце каждого хода.

Победа при этом наступает **один раз**: после записи исхода дальнейшие заявки не принимаются.

## 7. Отношение к существующим законам

```text
WIN_CHECK_LAW    остаётся источником условия победы
                 §12, пункт 1 — грамматика — ЗАКРЫТ здесь §5
ENOUGH           первый заявитель по §6
GRANT            §6, §7 — грантовые слоты порядок не сохраняют
TURN_STEP_LAW    шаг 9 — место вызова
REQUIEM          §7 — источник повторяемых заявок
```

Ни один из перечисленных не заменяется.

## 8. Что сюда не входит

```text
поражение
```

Модуль называется по победе и занимается победой. Поражение живёт отдельно.
