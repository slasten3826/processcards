Этот документ называет поверхность CLI как **рендера для машины**. Он не описывает реализацию.

## 1. Две поверхности

У ядра две законные поверхности, и каждая команда обязана объявлять, какой пользуется.

```text
полная      inspect.snapshot, core.interaction
            полная информация, для отладки

честная     view.observe
            только то, что игрок вправе знать
```

```text
команды ИГРЫ обязаны использовать честную поверхность   -- ЗАМЕНЕНО
команды ОТЛАДКИ обязаны быть помечены как отладочные
```

Команда, показывающая игроку больше, чем даёт `view.observe`, без пометки — нарушение закона.

Первая строка заменена `DEV_CLI_LAW §3`: умолчание — полная поверхность, честная включается тумблером. Обязанность объявлять поверхность и помечать отладочные команды сохраняется.

## 2. Сессия

```text
session new <seed> [trumps]   создать и сохранить
session show                  наблюдение и легальные действия
session do <action>           применить действие и сохранить
session drop                  удалить
```

Гарантии:

```text
детерминизм       сид плюс последовательность действий однозначно
                  определяют состояние
персистентность   состояние переживает завершение процесса
одна активная     одновременно существует одна сессия
```

Режим нескольких параллельных сессий не вводится.

## 3. Расстановка позиции

```text
session plant <card> <zone> [slot]
```

**Отладочный примитив, а не ход.** Не является действием игрока и не проходит через протокол.

Обязательства:

```text
изъять карту из прежней зоны
восполнить оставленную дыру по правилам зоны:
    manifest — открытой картой, latent и targets — закрытой
сохранить или явно задать информационное состояние
оставить доску в валидном состоянии
```

Если восполнение невозможно (пустая дека), команда обязана сообщить об этом, а не оставить дыру молча.

Причина существования: расстановка вручную порождает невалидные позиции, и тогда проверки измеряют стенд, а не игру.

## 4. Таблица совпадений

```text
session fits
```

Для каждой карты руки — слоты, к которым она подходит по топологии, и отдельно слоты, доступные только через джокер `☶`.

```text
MINOR-71   FLOW/CYCLE       fit:[1,3]     joker:[]
MINOR-82   CONNECT/RUNTIME  fit:[1,2,3,6] joker:[]
```

Честная поверхность: показывает только руку игрока и открытый манифест, то есть то, что игрок и так видит.

## 5. Трасса

```text
session trace [turns]
```

События, сгруппированные по ходам, с отметками границ шагов.

```text
одна группа = один ход, от начала до turn_closed
границы шагов видны
козырные события отделены от минорных
```

Требование к формату: **аномалия должна быть заметна глазом**, без внешних фильтров.

## 6. Справка по карте

```text
card <id>        пара операторов, класс, текущая зона
find <A>/<B>     идентификатор карты с такой парой
```

Отладочные: раскрывают личность карты независимо от её информационного состояния.

## 7. Откат

```text
session undo [n]        отменить последние n действий
session save <name>     снимок
session load <name>     восстановление
```

Реализуется переигрыванием от сида либо снимком состояния; закон не выбирает способ, но требует, чтобы результат был неотличим от прямой игры.

## 8. Позиционные метрики

```text
session metrics
```

Считаются **по позиции**, не по прогону, и потому не зависят ни от какой политики.

```text
легальных ходов в текущей позиции
заперта ли позиция: есть ли хоть одна легальная пара
плотность козырей в деке
размеры зон
```

Закон, ради которого раздел существует:

```text
число, полученное через политику, отвечает только на вопрос,
что делает эта политика
```

Поэтому метрики, зависящие от прогона — длина партии, take-rate, причина завершения — **не относятся** к этой команде и не должны в неё попадать.

## 9. Что не вводится

```text
машинно-структурный вывод вместо текста
более умная политика в качестве источника статистики
несколько параллельных сессий
```
