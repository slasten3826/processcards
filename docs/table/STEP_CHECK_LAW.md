Этот документ называет содержимое **двух** проверочных шагов хода. Сами шаги описаны в `TURN_STEP_LAW §10` и `§11`; здесь сказано, что они делают.

Первая редакция знала один шаг — девятый. Поражение получило собственный шаг: `LOSS_IS_ITS_OWN_STEP_2026-07-30`.

## 1. Оба шага — обращения

```text
шаг 9  WIN CHECK   ход СПРАШИВАЕТ: кто-нибудь выиграл?
шаг 10 LOSE CHECK  ход СПРАШИВАЕТ: следующий ход возможен?
```

Ни один не проверяет сам и не содержит условия. Оба обращаются.

Спрашивающих у модуля теперь трое: два шага и козырь с заявкой. Вход у модуля по-прежнему один — `WIN_MODULE_LAW §2`.

## 2. Границы принадлежат ходу

```text
step_win_check_begin        step_lose_check_begin
   обращение                   обращение
step_win_check_end          step_lose_check_end
```

События шагов эмитит ход. Модуль про существование шагов не знает.

Имена событий первой редакции — `step_check_begin` / `step_check_end` — заменены: одно имя на два шага не различает, который из них спрашивал.

## 3. Одна точка

```text
КАЖДОЕ обращение эмитится из ОДНОГО места в коде
```

Требование поштучное: у каждого шага ровно одна точка, а не одна точка на оба. Пока их две на шаг, вторая однажды отстанет от первой.

## 4. Отношение к существующим законам

```text
TURN_STEP_LAW §10   описывает девятый шаг и почему он после TRUMP.
                    Не заменяется
TURN_STEP_LAW §11   описывает десятый шаг и условие поражения.
                    Не заменяется
WIN_MODULE_LAW §2   форма обращения: подпись TURN
```

Подпись десятого шага здесь не назначается: она принадлежит модулю, а модуль ещё не переименован — `LOSS_IS_ITS_OWN_STEP_2026-07-30 §9.1`.
