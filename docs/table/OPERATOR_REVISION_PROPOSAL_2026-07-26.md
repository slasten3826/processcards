## 2. Предлагаемые законы

### 2.1. `▽ FLOW` — кольцо

```text
▽ = повернуть кольцо на 1 шаг

кольцо:
  topdeck -> latent1 -> latent2 ... -> latent6 -> низ деки -> ... -> topdeck

движутся:      только not-known карты
анкеры:        known и revealed
перескок:      not-known карта переезжает в следующую not-known позицию
target-зона:   в кольцо НЕ входит
направление:   одно
```

Следствия, которые надо назвать как часть закона:

```text
latent1 = закрытый draw из деки
latent6 = уход карты под низ деки
кольцо замкнуто -> FLOW безубыточен
цена FLOW = занятый оператор хода, ничего больше
known в середине ряда работает плотиной
градиент возраста: колонка 1 свежая, колонка 6 старая
```

Почему направление одно:

```text
выбор направления есть ☳ CHOOSE внутри ▽ FLOW,
а FLOW по канону — поток до различения;
и движутся только not-known карты,
значит у выбора нет информации, на которой он мог бы стоять
```

### 2.2. `☵ ENCODE` — на известном

```text
☵ работает только с картами, которые уже known
known — предусловие, а не награда
```

Разделение с `OBSERVE` становится строгим:

```text
☴ скрытое  -> известное     добыча
☵ известное -> позиция       применение
```

Незакрытое: **чем ENCODE платит за верную расстановку.** Первая версия
(карта становится `known` плюс метка `prepared`) отвергнута как дублирующая
`OBSERVE`. Выплата нужна, но она не может быть информацией.

### 2.3. `☷ DISSOLVE` — курация

```text
1. latent[i] уходит в grave
2. пополнение слота: из deck ИЛИ из grave, по выбору игрока
3. карта, взятая из grave, входит known
```

Глагол меняется с «уничтожить» на «курировать». Это даёт `grave` обратный путь.

### 2.4. `☶ LOGIC` — джокер

```text
один commit в этом ходу проходит без проверки смежности
```

`☶` перестаёт быть обменом материалом и становится `rules(x)`: легальным
становится то, что законом не было.

Ручки цены, не выбранные: раз в ход / пока карта в `play` / раз за партию.

### 2.5. `☲ CYCLE` — расщепление

```text
БАЗА
- зона занята: повторить НИЖНИЙ (самый старый) козырь зоны
- зона пуста:  1 draw procedure, затем discard 1 из руки
- ёмкость зоны 2

КРУГ 7
- повторить ВЕРХНИЙ (самый свежий) козырь
- ёмкость зоны 3
- страховки нет
```

Повтор козыря — **не** draw procedure, поэтому ветка повтора не несёт trump
risk. Ветка страховки несёт его полностью, как сейчас.

## 3. Точные расхождения с текущим каноном

### `operators/FLOW.md`

```text
§4  «▽ works on hidden AND known»
    -> предложение: known становится анкером, движется только not-known

§3  «Direction: left or right»
    -> предложение: одно направление

§3,§6  три отдельных пространства targets / latent / deck,
       каждое вращается внутри себя
    -> предложение: deck+latent одно кольцо, targets исключены

§9  открытый вопрос «circular rotation или explicit top/bottom step»
    -> предложение отвечает: кольцо
```

### `operators/ENCODE.md`

```text
§3  «not-revealed включает hidden и known»
    -> предложение: только known

§6  pair law «☵☴ — observe hidden state and then encode it»
    -> предложение делает эту связку базовым законом, а не направлением пары
```

### `operators/DISSOLVE.md`

**Прямой конфликт, требующий явного решения.**

```text
§2  «☷ now is not: ... grave interaction»
    -> предложение: grave становится источником пополнения

это не уточнение, а отмена одного из «what it is not».
Либо §2 переписывается, либо предложение отклоняется.
```

### `operators/LOGIC.md`

```text
§1,§3  «☶ = swap one revealed minor-card with one card from hand»
       legal target class включает grave
    -> предложение: обмен материалом убирается целиком,
       grave освобождается под DISSOLVE

это полная замена глагола, а не правка параметров.
```

### `operators/CYCLE.md`

```text
§1,§3  «☲ = perform 1 draw procedure, then discard 1 from hand»
    -> предложение: это становится ветвью страховки, а не основным законом

§4  role split «☰ grows hand / ☲ refreshes hand / ☳ reclaims board material»
    -> предложение меняет роль ☲ на «повтор», ветвь refresh остаётся резервной

§9  открытый вопрос «whether weak ☲ should stay exactly draw 1 then discard 1»
    -> предложение отвечает: нет
```

## 4. Что не трогается

```text
☰ CONNECT   рост руки
☴ OBSERVE   добыча информации
☳ CHOOSE    возврат материала с доски
☱ RUNTIME   установка
△ MANIFEST  выход
```

`OBSERVE` при этом меняет **значение** без изменения закона: он перестаёт быть
самодостаточным ходом и становится входом в информационную экономику, потому
что `ENCODE` теперь требует его результата.

Также не трогается:

```text
DECK_AND_SETUP_LAW, MOVE_FIT_LAW, REPAIR_PHASE_LAW,
TRUMP_FLOW_LAW, TARGET_ZONE_LAW, GRAVE_LAW
```

`GRAVE_LAW` следует перечитать отдельно: предложение по `DISSOLVE` даёт могиле
обратный путь, и не проверено, что действующий закон могилы это допускает.

## 5. Открытые вопросы

```text
1. Чем ENCODE платит за верную расстановку, если не информацией.
2. Легальны ли латентные слоты для ☵ сейчас (§4 ENCODE.md перечисляет
   latent, но при переходе на «только known» набор надо перепроверить).
3. Цена джокера LOGIC.
4. Совместимо ли предложение по DISSOLVE с GRAVE_LAW.
5. latent6 -> низ деки делает порядок колоды управляемым;
   комбо с ORACLE / UNVEIL / FOOL-дрелью может дать больше контроля,
   чем задумано.
6. Удвоенные операторы: ▽▽ ☵☵ ☲☲ — открытый вопрос во всех family-файлах,
   и ревизия его не закрывает. Для кольца ▽▽ особенно неочевидно:
   два шага или двойная область.
7. Target-зона: FLOW из неё уходит. Её оператором остаётся OBSERVE,
   действующими лицами — козыри. Проверить, достаточно ли этого.
```

## 6. Условие принятия

Ни одно правило здесь не проверено плейтестом. Предлагаемый критерий для
каждой ревизии — инверсия take-rate соответствующего оператора:

```text
ревизия сработала  ⟺  take-rate вырос значимо
ENCODE   1.9% -> ?
DISSOLVE 2.3% -> ?
FLOW     1.5% -> ?
CYCLE    1.4% -> ?
LOGIC    36.2% -> должен остаться в том же порядке,
                  иначе замена глагола сломала рабочий оператор
```

Ограничение метода — в `../chaos/SIM_BOT_AS_INSTRUMENT_2026-07-26.md`: жадный
survival-бот честно мерит реактивные операторы и плохо мерит всё, что требует
плана или удержания.
