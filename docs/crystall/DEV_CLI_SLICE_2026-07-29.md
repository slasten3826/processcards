## 1. Несущее решение: форма проверки

`DEV_CLI_LAW §2` объявляет единицей работы кристалл, доведённый до `▲`, и оставляет открытым, что это значит. Здесь это закрывается.

```text
проверка — модуль, который ЦИТИРУЕТ раздел КРИСТАЛЛА
           и отвечает за него одним из трёх исходов
```

Цитата идёт в `◈`, а не в `⊞`, потому что код манифестируется из кристалла. Цепочка уже существует и достраивать её не надо:

```text
проверка -> раздел кристалла -> закон, объявленный источником кристалла
```

Правка от 2026-07-29. В первой редакции здесь стояло «цитирует раздел закона». Это перепрыгивало слой — `layer_boundary_collapse` — и немедленно упёрлось в код: пятнадцать проверок `LOGIC_JOKER_SLICE §9` пронумерованы по кристаллу, и это правильно, а контракт требовал выдумать отображение на разделы закона, которого не существует.

Следствие: закон без кристалла проверку иметь **не может**. Это не ограничение, а то, ради чего слои и разделены: непокрываемость такого закона становится видимой, а не маскируется прямой цитатой.

## 2. Три исхода, а не два

```text
OK    закон соблюдается в проверенных позициях
FAIL  найдено нарушение
SKIP  проверка отказалась: предмет недостижим в текущей сборке
```

`SKIP` несущий. Он отличает **отложенный** закон от **непокрытого**:

```text
непокрытый   ни одна проверка его не цитирует
отложенный   проверка есть, она отработала и отказалась
```

Этим же закрывается `DEV_CLI_LAW §11.2`. Закон, который нельзя проверить до готовности козырной машины, получает проверку, возвращающую `SKIP` с причиной, а не отсутствие проверки.

## 3. Результат проверки

```lua
{
    cites   = "TURN_STEP_SLICE_2026-07-28 §7",
    status  = "OK" | "FAIL" | "SKIP",
    reached = "played" | "planted",
    effects = "all" | "none" | "<список>",
    detail  = "строка, обязательна для FAIL и SKIP",
}
```

Формат цитаты — имя файла кристалла без расширения плюс номер раздела. Однозначно и проверяемо механически.

`reached` — требование `DEV_CLI_LAW §7`. Позиция, полученная расстановкой, валидна и не обязана быть достижимой, поэтому исход обязан это нести.

`effects` — потому что `OK` при `effects=none` и `OK` при `effects=all` разные утверждения.

## 4. Модуль проверки

```lua
-- src/check/<name>.lua
return {
    cites = {"TURN_STEP_SLICE_2026-07-28 §7"},
    run = function(opts) return {results = {...}} end,
}
```

```text
cites   разделы кристалла, за которые модуль отвечает
run     возвращает список результатов раздела 3
opts    seeds, steps, effects
```

Существующие проверки переносятся в эту форму: `logic_joker_check`, `step_invariant`, `observation_audit`, `session_check`.

## 5. Реестр и покрытие

```lua
src/check/init.lua
    M.modules()   -- перечисление модулей
    M.run(opts)   -- прогон всех, сбор результатов
    M.coverage()  -- два перехода, раздельно
```

Покрытие считается **в два шага**, потому что переходов два и ломаются они по-разному:

```text
⊞ -> ◈   закон объявлен источником хотя бы одного кристалла
◈ -> ▲   раздел кристалла процитирован хотя бы одной проверкой
```

```text
закон покрыт  <=>  есть кристалл, объявляющий его источником,
                   и хотя бы один раздел этого кристалла процитирован
```

Источник кристалла читается из строки `источник: ../table/<ИМЯ>.md` в шапке. Кристалл без такой строки не участвует в первом переходе.

```text
lua cli.lua check          прогон всех, сводка по исходам
lua cli.lua check <name>   один модуль
lua cli.lua coverage       оба перехода
```

Вывод:

```text
⊞ -> ◈   законов 94, объявлено кристаллами <a>
◈ -> ▲   разделов кристаллов <b>, процитировано <c>
покрыто законов <d>

TURN_STEP_LAW        TURN_STEP_SLICE_2026-07-28   1/9
WIN_CHECK_LAW        нет кристалла                 —
```

Цитата на несуществующий кристалл или раздел — `FAIL` реестра, не молчание.

## 6. Ось эффектов

`DEV_CLI_LAW §4`, `§5`.

```lua
-- setup.start_game
state.setup_options.enabled_effects = normalize_effects(opts.enabled_effects)
-- nil = все, {} = ни одного, {SHUFFLE = true} = только названные
```

```lua
-- trump.lua, resolve_trump_card, между двумя событиями
transition.emit(state, "trump_effect_begin", {card_id = card_id, trump = name})

if effect_enabled(state, name) then
    ... существующее тело без изменений ...
else
    transition.emit(state, "trump_effect_stubbed", {card_id = card_id, trump = name})
end

transition.emit(state, "trump_effect_end", {card_id = card_id, trump = name})
```

Единственная точка вмешательства. Всё до `trump_effect_begin` и всё после `trump_effect_end`, включая `resolve_trump_zone_entry`, не трогается.

`normalize_effects` повторяет форму `normalize_enabled_trumps`: принимает имена, `TRUMP-<n>` и числа.

## 7. Заголовок журнала

`DEV_CLI_LAW §6`.

```text
# seed=7 trumps=full effects=none draw=turn
```

```text
поле       значения
seed       число
trumps     full | none | список
effects    all | none | список
draw       turn | free
```

Отсутствие поля читается как умолчание: `effects` — `all`, `draw` — `turn`. Журналы, записанные до введения оси, остаются валидными.

Разбор и запись — `session.read` и `session.write`.

## 7a. Ось добора

`DEV_CLI_LAW §8`.

```text
draw=turn   команда draw вне хода ОТКАЗЫВАЕТСЯ
draw=free   команда draw вне хода разрешена, без счётчика
```

Отказ громкий и в той же форме, что `unknown_action`: переход с `error = "free_draw_disabled"`, а не голое `nil, err`. Голая пара на этой границе — ровно то, из чего выросли нераспознанные отказы (`chaos/UNRECOGNISED_REFUSALS_2026-07-29.md`), и повторять её нельзя.

Гейт стоит на **действии**, а не внутри `game.draw_to_hand`: построители позиций (`sim/scenarios`, `session.plant`) зовут функцию напрямую и живут по `DEV_CLI_LAW §7` — они не действия и легальностью не связаны.

Ось живёт в журнале, поэтому переигрывание журнала с `draw=free` на машине без настроек даёт ту же партию.

```text
session new <seed> <surface> <effects> [draw]
```

Четвёртый аргумент необязателен и по умолчанию `turn`.

Гейт стоит **в ядре**, не в CLI: `draw` — обычное действие `apply_action`, и любая внешняя поверхность обязана получить тот же отказ. Флаг хранится в состоянии рядом с `enabled_effects`.

Проверка условия поражения, встретив `draw=free`, обязана вернуть `SKIP` с причиной — `DEV_CLI_LAW §8`, тот же класс, что пометка расстановки в `§9` настоящего кристалла.

## 8. Тумблер

`DEV_CLI_LAW §3`.

```text
умолчание          полная поверхность
--honest           честная
```

Флаг не пишется в журнал и не влияет на переигрывание.

```text
session show            inspect.snapshot + interaction
session show --honest    view.format(view.observe)
```

Отладочные команды продолжают печатать баннер по `MACHINE_CLI_LAW §1`, эта часть закона не заменена.

## 9. Пометка расстановки

`DEV_CLI_LAW §7`.

```lua
session.rebuild(log) -- дополнительно возвращает planted = true,
                     -- если журнал содержит хотя бы одну запись plant
```

Проверка, строящая позицию через `session.plant` или прогоняющая журнал с `planted`, обязана вернуть `reached = "planted"`.

Сводка прогона печатает число результатов, полученных через расстановку, отдельной строкой.

## 10. Вырожденные случаи

```text
модуль без cites              ошибка реестра
цитата на исчезнувший раздел  FAIL реестра
FAIL или SKIP без detail      ошибка реестра
effects со списком, где имя
  не из TRUMP_CANON           ошибка разбора при старте
пустой список effects         эквивалент none
```

## 11. Проверки среза

```text
1. effects=none: в трассе нет ни одного эффекта козыря,
   но есть trump_flow_entry, step_trump_begin, step_trump_end
   и вход в козырную зону
2. effects=none и effects=all: состав деки после setup совпадает
   покарточно
3. effects=SHUFFLE: срабатывает только SHUFFLE, остальные дают
   trump_effect_stubbed
4. заголовок с effects переживает запись и чтение
5. заголовок без effects читается как all
6. цитата на несуществующий раздел даёт FAIL реестра
7. проверка, прошедшая через plant, возвращает reached=planted
8. coverage: сумма цитируемых и непокрытых равна числу разделов
```

Пункт 2 — контрольный: он отличает ось эффектов от оси присутствия. Расхождение означало бы, что заглушка меняет игру, а не только эффект.
