## 2. Диагноз

Четыре оператора из десяти практически не участвуют в игре: `FLOW`,
`DISSOLVE`, `ENCODE`, `CYCLE` — суммарно 32 выбора из ~2200.

Проверенная и отвергнутая гипотеза:

```text
"они мертвы, потому что им не хватает козырей"
неверно: у CYCLE закодены все 4 ребра, у FLOW все 3
```

Настоящая причина:

```text
все четыре работают со скрытым слоем,
а у скрытого слоя нет ни информационной экономики,
ни обратного пути
```

Развёрнуто:

```text
ENCODE   тасует карты, о которых игрок ничего не знает -> нулевое ожидание
FLOW     перемешивает неизвестное с неизвестным         -> нулевое ожидание
DISSOLVE платит материалом в grave, откуда нет возврата -> чистый убыток
CYCLE    draw 1 / discard 1                             -> размен в ноль
```

Отдельно, но из того же корня: `OBSERVE` играется чаще всех (55.8%), а его
информация ни во что не конвертируется. Знание есть, применить нечем.

И отдельная находка: `grave` инертен. Единственный найденный путь обратно —
козырь `SHUFFLE`. То есть в игре сейчас **карма без метаболизма**, ровно в том
смысле, который описан в `KARMA_METABOLISM.md` в slastack: память без переработки
вырождается в тюрьму. `DISSOLVE` и есть оператор метаболизма, и он мёртв
потому, что метаболизировать некуда.

Вывод: лечить надо не операторы по одному, а слой.

## 3. Предлагаемые правила

Каждый оператор различается тем, **что он требует на входе**.

```text
▽ FLOW      не требует ничего        грубое движение
☵ ENCODE    требует знания           точная запись
☷ DISSOLVE  требует могилы           курация
☶ LOGIC     требует себя             легализация
☲ CYCLE     требует козыря           повтор
```

### 3.1. FLOW — кольцо

Дека и скрытые латентные слоты перестают быть разными сущностями. Это одно
кольцо, и `FLOW` его крутит.

```text
▽ FLOW — RING

topdeck -> latent1 -> latent2 ... -> latent6 -> низ деки -> ... -> topdeck

- двигаются только not-known карты
- known и revealed стоят на месте и держат поток
- not-known карта переезжает в следующую not-known позицию,
  перескакивая анкеры
- target-зона в кольцо НЕ входит
- направление одно
```

Следствия:

```text
latent1  = закрытый draw из деки
latent6  = уход карты под низ деки
кольцо замкнуто -> FLOW безубыточен (потеря принадлежит DISSOLVE)
цена FLOW = только занятый оператор в этом ходу
известная карта в середине ряда работает плотиной
у доски появляется градиент возраста: колонка 1 свежая, колонка 6 старая
```

Почему направление одно, а не два:

```text
выбор направления — это ☳ CHOOSE внутри ▽ FLOW,
а FLOW по канону есть поток ДО различения

механически: двигаются только not-known карты,
значит у выбора направления нет информации, на которой он мог бы стоять;
это не решение, а шум решения
```

### 3.2. ENCODE — на известном

```text
☵ ENCODE — WRITE THE KNOWN

- ☵ работает только с картами, которые уже known
- known НЕ является наградой ENCODE; это его предусловие
```

Разделение с `OBSERVE` становится чистым:

```text
☴ OBSERVE  скрытое -> известное    добыча информации
☵ ENCODE   известное -> позиция    применение информации
```

Открытый вопрос, оставленный сознательно: чем именно ENCODE платит за верную
расстановку. Первая версия (карта становится known + слот помечается
`prepared`) отвергнута в этой же сессии как дублирующая OBSERVE. Выплата нужна,
но она не должна быть информацией.

Предпосылка к проверке: латентные слоты должны быть легальным пространством
для `☵`. Если сейчас нет — это расширение, без которого правило не работает.

### 3.3. DISSOLVE — курация

```text
☷ DISSOLVE — CURATION

1. latent[i] уходит в grave
2. пополнение слота: из деки ИЛИ из grave, по выбору игрока
3. карта, взятая из grave, входит known
```

Глагол меняется с «уничтожить» на «курировать»: игрок решает, что похоронить и
что поднять обратно. Материал не теряется, он движется между скрытым и
погребённым. Это единственный оператор, который смотрит в могилу, — и это даёт
`grave` обратный путь, то есть метаболизм.

### 3.4. LOGIC — джокер

Текущий `☶` делает обмен материалом (рука ↔ revealed public/grave). Это
территория `CHOOSE` и `CONNECT`, а не `rules(x)`. Во всех остальных слоях стека
LOGIC проверяет и обосновывает; только в игре он торгует. Отсюда ощущение, что
оператор неправильный.

```text
☶ LOGIC — JOKER

Один commit в этом ходу проходит без проверки смежности.
```

Это буквально `rules(x)`: легальным становится то, что законом не было. И это
совпадает со смыслом кристалла `FREE_WILL`: `☳` выбирает, `☶` обосновывает
после.

Ручки цены на потом: раз в ход / пока карта LOGIC в игре / раз за ран.

### 3.5. CYCLE — расщепление

`draw 1 / discard 1` — размен в ноль, отсюда 1.4%. Экономику седьмого круга
забираем в базу, но с расщеплением, иначе аду нечего искажать, а база начнёт
промахиваться (зона пуста ~39% шагов).

```text
БАЗА ☲ CYCLE
- зона занята: повторить НИЖНИЙ (самый старый) козырь зоны
- зона пуста:  старое draw 1 / discard 1 как страховка
- ёмкость зоны 2

КРУГ 7 ☲
- повторить ВЕРХНИЙ (самый свежий) козырь
- ёмкость зоны 3
- страховки нет
```

Жест этажа: ад снимает страховку и отдаёт вершину стека вместо дна. Игрок
приходит на седьмой, уже зная глагол «повтори».

## 4. Следствия для этажей ада

```text
КРУГ 1 ▽  forced FLOW крутит кольцо НАЗАД:
          стол утягивается обратно в деку.
          Подложка забирает то, что уже выложила.
          Ноль новых понятий — то же кольцо, обратный знак.

КРУГ 3 ☷  Цербер съедает латентный ряд, после чего ряд собирается
          из grave в любом порядке, все карты known но не revealed.
          Сила этажа масштабируется глубиной могилы:
          этаж платит игроку его же накопленным остатком.
          Через ран протягивается нить — хоронить осознанно.

КРУГ 7 ☲  см. 3.5

КРУГ 8 ☶  база легализует свой ход, ад легализует доску:
          от самооправдания к подделке записи.
```

Общий закон, вытащенный в этой сессии:

```text
этаж ада должен искажать глагол, который у игрока уже есть.
если у оператора нет базового глагола — сначала база, потом ад.
```

## 5. Критерий проверки

Не мнение, а число. Тот же замер из раздела 1, прогнанный на конкретном этаже:

```text
этаж N работает  ⟺  take-rate его оператора на этаже инвертируется

CYCLE 1.4% -> высокий   круг 7 работает
CYCLE 1.4% -> 4%        круг 7 не работает
```

Так же для круга 1 по `FLOW`, круга 3 по `DISSOLVE`, круга 4 по `ENCODE`.

То же самое применимо к правкам базовой игры: если после 3.2 take-rate
`ENCODE` не поднялся, правило не сработало, как бы оно ни звучало.

Предлагаемый инструмент: отчёт `legal / chosen / take-rate` по операторам в
`src/sim`, гоняемый на каждый билд. Роль та же, что у `edge_stats` в proc-17.
